# learning-gate — two writes, and they are not the same write

Why: an agent finishing a task reaches for "save what I learned" as a ritual, and the corpus fills with
rows nobody reads. A memory is project knowledge; a skill edit develops the method.

It teaches and refuses nothing: the write goes ahead, and the session is told once per file and
content what it owes. A memory owes one line saying which of the conditions made it worth keeping,
or its removal. A workaround, a flag, a command to run first belongs in code, as a default or a
check, or in an issue that puts it there.

If it names a file that already says this, fix that file. Editing an existing memory: replace the rule
in place, or delete the file — never append a second version.

A skill edit answers instead: the category, whether a check could enforce it, what it displaces. A
sentence the skill already says is named, to keep in one place.

A file landing unasked is answered for late: `forge hooks --how learning-landed`.

Write it with `Write` or `Edit`, where the question comes first; through the shell `sed -i` carries
no content to read, so the question comes beside the write instead.

Not judged: whether the fact is true or useful. Only that the write was decided on.

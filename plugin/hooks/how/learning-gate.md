# learning-gate — two writes, and they are not the same write

Why: an agent finishing a task reaches for "save what I learned" as a ritual, and the corpus fills with
rows nobody reads. A memory row is project knowledge; a skill edit develops the method.

How to clear a memory write: apply the four conditions the refusal prints, then re-send and say in one
line which of them made it worth keeping. It asks once per file per session.

If it names a file that already says this, fix that file. Editing an existing memory: replace the rule
in place, or delete the file — never append a second version.

A skill edit answers three things instead: the category, whether a check could enforce it, and what it
displaces. A sentence the skill already says is refused outright.

How to write through it: `Write` or `Edit`. The shell route is closed — `sed -i` carries no content to
read, and the decision has to happen before the write. Reading is free. A program carrying a write
shape *and* quoting a guarded path is refused even when the path is prose, so assemble it from parts.

Not judged: whether the fact is true or useful. Only that the write was decided on.

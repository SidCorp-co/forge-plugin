# learning-gate — two writes, and they are not the same write

Why: an agent finishing a task reaches for "save what I learned" as a ritual, and the corpus fills with
rows nobody reads. A memory is project knowledge; a skill edit develops the method.

How to clear a memory write: apply the conditions the refusal prints, then re-send and say in one
line which made it worth keeping. The last condition is the one skipped: a workaround, a flag, a
command to run first belongs in code, as a default, a check or a refusal, or in an issue that puts
it there.

If it names a file that already says this, fix that file. Editing an existing memory: replace the rule
in place, or delete the file — never append a second version.

A skill edit answers instead: the category, whether a check could enforce it, what it displaces. A
sentence the skill already says is refused.

A file landing anyway is answered for late: `forge hooks --how learning-landed`.

How to write through it: `Write` or `Edit`. The shell route is closed — `sed -i` carries no content to
read. The write's target counts, spelled out or assembled, and not a path beside it; where the verb
is handed its file, every path in the command counts.

Not judged: whether the fact is true or useful. Only that the write was decided on.

# writes — what counts as one, for every gate that asks

Why: most edits arrive as `sed -i`, a heredoc or an interpreter opening a path, so a gate watching
tool routes sees a fraction.

After the call, the disk answers: a token naming a real file stamped at or after this call's request,
read from the command as written and again with a binding and a body's assembly resolved. Where the
text claims no write there, the tree must disagree with HEAD too: a `git checkout` restamps what the
next word only names. Where git cannot say, the stamp stands alone.

Before the call there is only text. A write verb counts in command position — a line's start,
after `;` `&` `|` `(` or `-exec`, an assignment prefix, or a wrapper (`sudo`, `xargs`, …). A library
call (`open(…, "w")`, `writeFileSync`) counts anywhere. Only a redirect names its target. A variable
takes an earlier command's assignment, not its own prefix; `$(…)` is text.

To mention one without writing: out of command position — a `--name` value — or in a data heredoc;
a `-c` body is code, so a verb there counts.

Not judged: what the write contains, or whether it belongs.

Not seen: a name no spelling produces — a glob's match, a command's output, a variable set
elsewhere, an inline `-c` assembly. Spell it, or reach for `Edit`.

# brief — a dispatch message nobody generated

Why: a typed message carries what the dispatcher believed about the method, and a run reads it
first. On 2026-09-23 five briefs carried a rebase order under text forbidding it (ISS-2148).

What to do: send what `forge brief ISS-nn --tree <the run's worktree>` prints (no `--tree`
for a run given none), whole and unchanged. A judge's aim at an issue — a deployment (`--judge --url`)
or an installed command-line program (`--judge --program`) — or at a requirement
(`--requirement REQ-n --url`): `forge brief -h`.

It teaches and never refuses: the dispatch goes as written, and the brief to send next time arrives
beside it. Which brief is a way of working, not kernel input — the run's own claim and lease are
where its job and state are held. What it judges: a dispatch to a role this plugin ships, by whether
the whole prompt is one the verb printed in the last ten minutes, and a judge's by whether it is the
judge's form, which names a deployment or an installed program and, except for a program judge, no
tree (ISS-3145). A line the verb writes to standard error is not the brief.

Said only where the tracker gates the project `strict`, or fast delivery is off. Otherwise the session
is told no brief was asked. Both are read per dispatch; a failed read keeps the teaching. `forge doctor`
prints the `gates` row.

Not judged: a role another plugin ships, and a general agent. Words are never read: a digest of the
whole is compared (ISS-2147).

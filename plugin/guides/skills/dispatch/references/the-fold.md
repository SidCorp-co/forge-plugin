# Folding a wave

The fold is the half that makes the next wave cheaper. A wave that dispatches and never folds has
spent the runs and kept none of what they learned.

## Where it is written

The project says where its own waves are recorded, and the project's record is where that is read
from — nothing here names a file, because the answer differs per repository and a path written into
method is wrong silently. A project that has never recorded one has no home for it yet, and saying so
is the fold's first finding.

## One section per run

Whatever the run reported, and in its own terms rather than the tracker's columns:

- What landed, and what it was released as.
- What the run filed, and where. "Filed on ISS-nn" is not a fact, it is a report about a write; open
  the thread and see the write. One that is not there is itself worth a section, because the run
  believed it had handed the work on and nobody has it.
- What a restart is owed for.
- What the run declined to do and why. A declined step is the most useful line in a report: it is
  either a gap in the method or a rule doing its job, and the two look identical from the outside.
- Where the wave took a lower-ranked issue, with the rank it overrode and the reason. A reason that
  shows up in three folds is a weight the ranking is missing, and it is filed as one.

## What the wave itself cost

Counted, never asserted. On one side, the dispatcher's own minutes and calls. On the other, the
readings the executors did not have to repeat and the runs that were never spent because triage
disposed of the issue first. Both halves go in the fold, including when the wave lost.

Where the run-cost record can be read per phase, the wave's own opening cost goes in beside the
figure it is meant to be reducing. A skill that claims a saving it has not measured is the habit this
one replaces.

## Closing the wave

The trees the runs worked in go, once what a verdict cites has been captured somewhere a verdict can
still cite it. A restart owed by anything that landed is stated to whoever runs the next wave, before
the next wave is dispatched — a role name, a hook or a skill that changed underfoot resolves against
the copy the session started with, and a run dispatched into that gap fails for a reason nothing in
its own report explains.

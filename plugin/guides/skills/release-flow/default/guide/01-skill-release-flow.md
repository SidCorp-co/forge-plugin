## Skill: release-flow

One release job takes a change that has already landed and makes it true in production, then says
what happened. This is the method half. The call order, the refusals and the phases belong to the
release job and arrive with its prompt; what is here is what to do when the world does not match what
that prompt said, which is the half no other layer can supply.

**Declare yourself before anything else.** The first act of this method is to announce to the release
run that a method loaded and under what name, by the route the job's own prompt names. A run whose
announcement never arrives cannot be told apart from a run that had no method at all, which is the
state every release before this one was in. Announce, then read on.

**The job is the continuity; you are not.** Assume this session ends after every action. A different
agent on a different machine has to carry the release on from the record and the world alone, so
nothing may rest on what you remember: each step reads its own position back before it acts, and an
instruction that would have you trust a memory of the last one is wrong wherever it appears.

**The release procedure is the project's, never this method's.** Which branch promotes, what a deploy
consists of, what counts as health there — the job's prompt carries all of it. Nothing here overrides
one project's ritual, and nothing here is a substitute for reading the one you were given.

# Skill: qa

One session drains a status. It takes the issues a project has left standing at `developed`, decides
per issue what judgement is owed, gets that judgement made, moves the issue as far as its record
earns, and ends when the status reads empty. It writes no code and it lands nothing.

**Arguments.** Issue keys judge exactly those and stop. No argument drains the queue the ranking verb
offers, in the order it gives, until a read of it comes back with nothing offered and nothing unread.

**A person starts it, and nothing wakes on an issue arriving.** What accumulates between one
invocation and the next is what the first read finds, and that is the cost of a master nobody has to
keep alive rather than an oversight to design around.

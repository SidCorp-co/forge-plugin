## Phase 3 — Read what has to be witnessed, and get that judgement made

**The plan says which criteria only somebody at the running product can witness**, under a heading of
its own, by number or as a considered `none`. That answer is the decision, and it is read rather than
re-derived: the run that wrote it answered before the code existed, where a reader of a finished diff
answers about a change already in front of them. It is also what the person's look before release is
asked for, so a set named here is a set somebody is going to be shown.

**Where it answers `none`, no judging run is dispatched.** Nothing is waited for and nobody is asked
to look. This session is the judge: it judges every criterion against the record and against what is
running, writes the verdicts under its own id citing the identity read in the phase before, and says
in the same breath that nothing here reaches a person.

**Where the plan carries no such section at all** — an issue planned before the section existed —
this session answers the question itself rather than defaulting. Defaulting to *nobody witnesses*
releases unjudged screen work; defaulting to *somebody must* spends a run on every change that never
touched a surface anyone sees. Say which reading was taken and what it rested on, in the record that
moves the status, which is what makes either reading safe to audit later.

**Where criteria are named, a judging run is dispatched for those**, one call per run through the
role this copy ships rather than a general agent with a model typed in beside it. The message carries
the issue, the criterion numbers the plan named, the deployment identity, the route to a rendered
state and what this project holds to reach one, and nothing else; the role decides its own model,
effort and tools, and its method is `forge guide qa judging`.

**The issue is that run's while it works, and this session lets it go before dispatching.** Whatever
reading this one took is already written; holding the lease past it would refuse the judge the very
claim its verdicts have to be written under, and waiting for the clock to run out is the cost the
whole shape was built to remove. Take the issue back once that run has reported, which is where the
phase below starts. A rule a checker already enforces stays
out of the message: the checker is its one home.

**The cap is the number of runs this project declared, and this session gets it in full.** Another
master separately at that number is not this one's concern, and the number is not permission to
exceed it.

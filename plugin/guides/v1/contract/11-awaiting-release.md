### `awaiting_release` — reads the verdicts and the verification, against the plan's flags and the release note field

One rung and two promises, because the tracker holds one status for both: the evidence is here to be
judged, and the change is running where it landed. Both are read at this one entry, so a record that
answers half of it earns nothing.

Judge every criterion on every outcome, not only on failure. A criterion is a claim too: correct one
the review proved impossible, in the open, and judge it as corrected. A verdict on the old wording
passes a claim the code cannot make.

The rung is where merged work waits for production, so the verification is read against what landed.
Where the production branch is a different one, promotion is a step outside this ladder, and whether
a person is waited for is the project's answer. Close it in the same run: no comment decides the
close, and a thread too long to return whole cannot refuse it.

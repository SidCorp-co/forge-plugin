### Release and routes — what a release proves, and the routes it shares

**A release is proven by the installed copy, never by the tree.** A rebase drops an identical version
bump without a conflict, leaving a manifest that names a version carrying none of the change. Read
the version and the commit off the installed copy by its own path. Where a host batches what it
builds, the thing serving is a head this change never was: keep the two facts apart on the record.

**Every route this plugin sees is the same route.** The CLI enforces, and the pre-hook applies the
same check to the tracker tool called directly. A delegated agent is a route, an argument form is a
route, and a uuid is checked as a key is. What a run has been shown of a thread is state this plugin
writes, keyed by the session an agent shares with the agents it delegates to. The tracker's own
screens are outside it, so a status they set is unearned. A check on the server is the tracker's to
add, and this contract is its specification.

**The verb is the document.** `forge advance --owed` carries the entry criteria for the status in
hand, and each verb's own `-h` the fields the tracker takes. Repeat neither.

**When the tracker will not answer, the verb refuses and the gate lets the write through.** A verb is
a step the run can retry, so it fails closed with the reason. A gate is a hold on a step the session
waits on, and a hold outliving that is a denial nobody chose: fit a gate's retries inside its
registered budget, pass the write unchecked past it, and print what went unchecked and the command
that checks it after the fact.

### `in_progress:build` — reads the plan and the branch

Take one read of every file the change touched, at the head the landing will use: where the project
asks a review, it is the pass the review is earned by, never a recheck, which answers findings. Post
a correction for a file the plan does not name before writing it. Scope does not grow in silence:
cleanup that could stand alone is debt for the Audit, not scope.

**A change that lands no file in the repository owes no branch**, and says
so in its plan as `Lands no file: yes`; an empty diff never stands in for that line. From `in_progress:test`
on it owes what any change owes.

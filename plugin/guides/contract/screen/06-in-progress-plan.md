### `in_progress:plan` — reads the confirmation and the code behind it

This place promises that somebody read the code. Leave it by deciding every ambiguity or saying
*none found*. A decision the run may make is recorded, not asked; what a person is asked is `forge
record question -h`.

Where the project asks for plan approval, `approved` reads the plan and criteria before the code, so
they are written here; elsewhere the run writes them as it builds. Never relax a criterion to match
what got built; correct it in the open. A correction that re-sizes the work climbs a rung and
never comes back down: the complexity is the reporter's claim, and what the work turned out to be is
the run's.

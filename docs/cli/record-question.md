# `record question` — a question asks somebody

**A question record asks a person on the issue's own screen, and the comment alone never did.** The
tracker keeps questions as rows of their own, read by the issue's decision panel and the project's
questions list, and for months this kind wrote only a comment. The write succeeded, the run parked,
the status moved, and the panel the person was pointed at stayed empty: on another project a
question addressed to the owner sat nineteen hours on the first-ranked issue before anyone found
there was something to answer (ISS-2317). The other way out was to refuse the kind and name the call
that does ask, and there was none: a run missing a credential writes the question record alone, with
no park, and a refusal would have left that case with no route at all. So the write asks.

**The ask goes before the comment.** The question route screens what it is sent and refuses on its
own rules, and a comment already up when that happens is the comment-only state this verb exists to
end. The other order fails differently: an ask that lands and a comment that does not leave a
question with no record beside it, and a run sending the call again would ask twice. That half is
answered by reading the issue's questions first: an open one offering the same readings in the same
order is the one the earlier call asked, so it is reused and its id printed, and the record it lacked
goes up. The lease goes before both: the comment's own renewal is where another run's lease refuses
the call, and an ask sent ahead of it leaves a question on an issue the caller had no right to write
to (ISS-3101).

**The recommendation is the run's to state, and is owed.** The route refuses a question with no
recommended option, on the ground that a person facing a queue owes a click rather than a decision.
A run that has to ask has already taken a reading by the time it writes — the method has it take the
one cheaper to reverse — so the number is there to give, and a default of the first reading would put
a recommendation in front of the person that nobody made. The field is asked for at the write and
excused at the read-back, so a question record from before it still satisfies a park.

**Asking moves nothing.** The tracker's ask leaves the issue at its status, and a park on an issue
that already waits on a person asks nothing twice, so `forge advance --park question` is unchanged:
it still builds what would settle the question from the readings, and never reads the recommendation.
The prompt and the option labels go as written, as the record's own payload block does, because the
readings are copied onto the record byte for byte and the person should meet the same words in both.

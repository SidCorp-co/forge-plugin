# A gate refuses kernel input and teaches the rest

A gate denies or blocks only over kernel input, and the `cm:why` beside that verdict names which. A
way of working the agent should choose is taught: the call goes ahead, and the message that would have
refused it, action first, arrives as context in the same place; a stop carries no context, so there
it is the answer's warning. A teaching is said once per thing it
is about, since an agent told twice reads the second as noise, and the refusal log does not count it.

What still refuses, and on which kernel input:

| Gate | Refuses | Kernel input |
|---|---|---|
| bash-guard | a command taking processes, a moved ref or uncommitted work nothing restores (FR-08) | run, state |
| issue-read-first | a raw tracker call of an action a verb wraps | the verb's pre-checks of a tracker-refused write |
| judge-writes | a judge's write past its own verdicts | state, transition, evidence |
| ask-decide | a question to the owner naming no owner subject, off a strict project | escalation |
| stop-check | the stop, while a lease stands silent or a process the turn started stands, or where `stop.agents` cannot say whose stop it judges | session, run; malformed input |

Every other gate teaches, brief and the comments a write owes among them.

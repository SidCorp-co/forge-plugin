# codex — the eval

Whether `forge codex eval`'s reading is a comparison at all, and what it can say about a log that
lost depth. What the eval compares, and what makes anyone run it: [the log](codex-the-log.md). Its
write at the mark: [the mark](stats-the-mark.md).

## Why a short reading is judged, and not only counted

A window line says what was selected and leaves the reader to decide whether it was evidence. So
either window falling short of a hundred answered consults is also judged, in a line saying the
reading is not a comparison and each way it fell short, in the words `forge stats eval` uses for its
runs (ISS-1328), because both evals answer in one envelope and a reader of one reads the other.

The log can lose depth as the run corpus can — ISS-189 recorded a finishing run deleting a log it had
redirected — and a log that did prints the same counts as a young one. Only a reading taken when it
was deeper separates the two, so the judgement also says how far back the log reaches against the
consult readings held on this device. A reading records the log's own floor, its first answered
consult, and not its recent window's, which on a deep log begins long after the log does; one
written before readings recorded that floor is read by its window's, which understates the depth
and never invents a loss. Where no reading reaches earlier the line says the record is silent, never
that the log was never deeper: a mark is a snapshot and not a history.

## Why every consult reading on the device is searched

A consult reading is held under no project, because the log it was taken over is the device's, one
file in the same configuration directory as the store the reading is kept in. So every consult
reading there was taken over this log, whichever checkout's consult crossed the mark, and the search
is the same set `--against` resolves.

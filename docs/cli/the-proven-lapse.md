# the proven lapse — the lease a write may take off a run that is gone

A write that has to take its own lease is [the short lease](the-short-lease.md); this is the other
field it may take one from.

The route above read *free* as *nothing in the field*. A lease that ran out long enough ago is free
too, and the field naming whoever left it there is a fact about the past rather than a claim on the
issue. So the write that met it paid the round the route was built to remove: a refusal naming
`forge claim`, the claim typed off that very line, and the identical call again. It is charged where
a wave is tidying up after runs that have finished, which is the case that arrives in batches — four
issues cost eight calls when this was measured (ISS-1660).

**What decides is the seam a reclaim already draws, and no second one.** A bare `forge claim` grants
a lapse older than the duration the holder itself named, and refuses a younger one because a run
inside a gate and a run that died leave that same record; it refuses again where the two clocks
cannot order the moment the lease becomes anybody's. The write asks that one question and takes the
lease exactly where the claim would have been granted it, so no write can take an issue the claim
beside it refuses. A change that dropped the age comparison instead would have taken the fresh lapse
with it, and the guard that stops a takeover mid-build has nothing to do with the round being
removed.

**The record keeps the word the typed reclaim kept**, because the crash park counts the reclaims of a
status to find where runs die, and a pickup that stopped being typed is no less a run that died
there. It also keeps the displaced run and the moment its lease ran out, which no other claim row
does: every other caller read a refusal naming both before it wrote, and this one read nothing at
all.

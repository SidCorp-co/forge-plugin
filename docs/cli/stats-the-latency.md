# `stats` — a class's seconds a call, and the bound that names one

## Why a class's seconds a call is in the comparison, and what its bound is not

A waiting share is one number over every class at once, so a fortnight in which the second model
doubled its answer time and a fortnight in which the harness needed more rounds read the same, and
the change that separates the two windows takes the blame either way. The seconds a call each class
took is the figure that tells those apart, and it costs nothing to take: the profile already folds
every call into `byClass` in the pass that builds it, so both windows carry it before the comparison
asks.

**A class's denominator is what it did and what a run looked up, and the mixture is printed rather
than removed.** The classifier files `forge record verdict -h` under the row `forge record verdict`
on purpose — a lookup of a verb's help belongs to that verb — so a class's calls are uses and
lookups together, at roughly one in nine over this corpus. Taking the lookups out of the count would
leave their wait in the sum and understate nothing but the arithmetic; so both sides print the count,
and a window whose runs had to look something up more often is visible as that rather than as a verb
that got slower.

**The bound that decides which class is named is a constant and not a floor measured off the
corpus.** An angle's floor is a pass of block profiles for one named scalar figure, and it is
computed beside the reading precisely so that the release step's mark writer never spends it; the
class set, unlike the angle set, is whatever the corpus classed, so a floor here would be that pass
once per class, inside the one assembly both mark writers store. The constant is stated on the screen
for the same reason the floors are: a reader who cannot see what named a class cannot judge the
naming.

**The minutes beside a named class are tool-minutes and say so.** Why a class's row is a sum and the
wall clock is split by a union instead is [stats](stats.md); what is this table's own is that the
figure beside a named class is neither of those two but a third thing built from them — a difference
of two means multiplied by a call count. Being derived from the sums, it inherits what they cannot
do, so the one misreading this table can produce is a saving quoted from it against a wall-time
figure, and the label is there to refuse that rather than to describe the arithmetic.

**A row's population belongs to the class table, so two readings classed by different tables share a
label and not a denominator.** The stored reading a `--against` or a `--since-release` puts in the
before window's place was classed when it was written, and this table's rows move: a row added, or a
pattern changed so that a call moves from one row to another, gives every figure on both rows a new
population. A difference taken across that is arithmetic on a definition rather than a movement in
what the harness spends, and the two windows disagree with nothing saying why. So the class table
carries a generation of its own, every profile carries the generation that classed it, and a row
whose population has moved since the stored reading's generation is named as not comparable and
carries no move at all. The rows the change left alone go on comparing, which is why the generation
is held per row rather than per table; a stored reading naming no generation is comparable on no row,
the table behind it being unreadable from here. The naming is its own line rather than a mark on the
row, because the listing caps and folds a row thin on both sides and a statement about what a figure
means cannot be the one the fold takes. Nothing stored is re-read or rewritten: what is owed a reader
comparing across such a change is the statement, and the statement is what this is.

The angle blocks this table is not one of, and what a measured floor buys where a figure has one, is
[stats — the angles](stats-the-angles.md).

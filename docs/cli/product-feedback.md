# `product-feedback`

**Core refuses no feature issue, so the lane is kept by the tool and the note.** A session using
only this CLI filed about forty product features straight as issues while the project held a
product layer, because `forge new --category feature` was an ordinary shape and no verb filed a
project's Feedback (`forge feedback` is the plugin's own backlog). Core's guide `what-is-an-issue`
says a feature never starts as an issue an agent filed, and leaves keeping that to the agent.

**A note, never a refusal.** `forge new --category feature` files exactly as before and prints the
route after it. A refusal would change an outcome core does not change, and a project that really
wants a feature issue has no flag to say so. Bug, enhancement and review print nothing.

**The target is checked before anything is sent.** Core takes exactly one of its seven targets and
refuses none or two only after a body was read; a stdin body is gone by then.

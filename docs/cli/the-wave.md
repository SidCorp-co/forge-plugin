# The wave — a dispatcher's record, and what a resume reads of it

A run mid-way leaves its status, its records and its worklog on the tracker. A wave mid-way used to
leave nothing until its fold: which issues went out, to which role and under which session lived in
the dispatcher's conversation, and every release that moved a hook or a skill ended that
conversation. `wave` and `fold` put the wave on its headline issue, so the restart reads it back
(ISS-818).

**They are the only kinds that take no lease.** Every other kind answers for the run holding the
issue. These answer for the wave, and the headline they are written on may be free or a member one
of the wave's own runs holds. A leased write there would either take a free issue from the run about
to be sent onto it — the claim triage is forbidden to leave — or be refused by the run already on
it. So each is a finder's write, as `forge comment` is: it renews the writer's own lease where it
holds one and otherwise leaves the field alone. The same reason makes each a call of its own:
`--also` rides a rung that moves a status and every run flag writes onto the lease, and a write that
touches neither can carry neither.

**A park is the one headline these refuse.** At waiting and needs_info the tracker reads a comment
as the person's reply and moves the issue on, so a dispatch record there would move a status that no
record earned. Refusing is cheaper than a rule about which headline to pick, and the choice stays the
dispatcher's.

**What goes in is what the dispatcher knows and nothing a run will write.** No status and no
outcome: both are read from each member at the moment of the resume, because a copy would be stale
the moment the run moved. A dispatch counts as done only when every member is closed or dropped; a
parked member is a run the fold still has to resume, so it keeps its dispatch open. The runs are
counted one per dispatch, since a batch is one run.

**A wave has an end, and the end is a record rather than a reading of statuses.** Every member can
be closed with the fold still unwritten, and a restart then owes the fold, not a new wave. That is
why a fold closing no dispatch is refused: two folds in a row leave every reader printing the same
thing, and a write nothing reads is an input dropped. What a fold closed is counted at the read
rather than stamped, because the page already orders the records.

**It is the one part of `resume` that reads an issue other than the one asked for.** So it prints
only where the headline holds a record of either kind, and every other issue prints what it did.
Each member is read softly: one the tracker will not answer for is a line carrying the tracker's own
words rather than a resume that exits on it.
